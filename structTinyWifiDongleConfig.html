Detailed Description

Settings of the dongle; every field has a usable default except the SSID.

Pass it to TinyWifiDongle::begin(). String pointers only have to stay valid during that call.

◆ framesFromHost

uint8_t TinyWifiDongleConfig::framesFromHost = 0

Raspberry Pi Pico only: number of frame buffers for frames coming from the host (mostly acknowledgements). 0 = the default of the chip: 16 on the RP2350, 8 on the RP2040. The two directions have separate pools, so a burst towards the host cannot take the buffers that the host's acknowledgements need. Ignored on the ESP32.

◆ framesToHost

uint8_t TinyWifiDongleConfig::framesToHost = 0

Raspberry Pi Pico only: number of frame buffers (about 1.5 KB each) for frames on their way to the host. 0 = the default of the chip: 48 on the RP2350 (Pico 2 W), 24 on the RP2040 (Pico W). More buffers absorb bursts of traffic, so fewer frames are dropped (a dropped frame slows a download down), at the price of RAM. Ignored on the ESP32.

◆ pinUsbTask

bool TinyWifiDongleConfig::pinUsbTask = true

Run the TinyUSB device task on the CPU core that runs the USB interrupt. The Arduino core starts that task without a core affinity; the TinyUSB driver of the ESP32-S2/S3 (0.21.0) has cross-core races between task and interrupt that make the send path stall under load. Keep this on unless you start the USB stack yourself (needs manageUsb).

uint32_t TinyWifiDongleConfig::stallTimeoutMs = 1000

If sending to the host makes no progress for this many milliseconds, the device is disconnected from USB and re-enumerated (the host sees the card being replugged and restarts the connection). 0 = never reset.
